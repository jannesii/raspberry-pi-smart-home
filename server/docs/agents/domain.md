# Domain docs

This repo uses a single-context layout: `GLOSSARY.md` and `docs/adr/`
at the repository root.

Before exploring a feature, read the root glossary and ADRs relevant
to that feature. If they do not exist yet, proceed; `/domain-modeling`
creates them when terms or decisions are resolved.

Use glossary terms in issues, proposals, hypotheses, and tests. If an
existing ADR conflicts with a proposed change, call out the conflict.
